# gdp-ts authorization proofs

Research date: 2026-11-10. This note records findings and recommendations. It is not an accepted ADR. No application code, dependency, or tool config was changed.

## Recommendation

**Adopt later.** The pattern can help when a feature has protected reads or writes with several callers. Current Hono features expose Better Auth and API docs; Effect has a health feature. There is little local business authorization to protect now. More important, the only npm release has verified forgery gaps. Wait for a corrected release and test it with this repo's complete lint and compiler config before a small feature trial. Sources: [Hono routes](../../apps/hono/src/app/routes.ts), [Effect health service](../../apps/effect/src/features/health/service.ts), and the release checks below.

## Verified facts

### Types and identity

- `name()` wraps one to three values and gives each a generic name inside a callback. `Named<N, A>` keeps `N` invariant with a private symbol member and a function type. `Proof<Kind, About>` uses a similar member for the tuple of names. Under strict compiler checks, normal calls reject a missing proof, a failed check that still includes `null`, a proof for another name, and `never`/`unknown` substitutions for names. Naming the same ID twice gives incompatible names. These are **type identities**, not a runtime comparison of IDs. Sources: [current implementation](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/src/index.ts), [type tests](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/test/types.ts).
- The strong claim that proofs always bind the exact runtime value is false. `{ ...project, value: other.value }` keeps the phantom name and replaces its value. Published 0.1.0 also accepts `{ ...weakProof, kind: "StrongKind" }`. I reproduced both with TypeScript 7.0.2, `strict: true`, and `noUncheckedIndexedAccess: true`. The two caller files passed Oxlint 1.91.0 with the repo config plus Ultracite's GDP preset. At runtime, both operations used the unchecked value. Negative controls for a different named argument and a missing proof produced the expected compiler errors. Sources: [published artifact](https://registry.npmjs.org/@gdp-ts/core/-/core-0.1.0.tgz), [value replacement report](https://github.com/rauchg/gdp-ts/issues/11), [kind fix](https://github.com/rauchg/gdp-ts/pull/18).
- Proof authority is not unique to a prover instance. Two `defineProof("SameKind")` calls can produce compatible proofs about the same names. The kind string and type structure define compatibility. A separate interface for each proof kind helps union inference; type aliases need `NoInfer` in the documented alternative. Sources: [implementation](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/src/index.ts), [recipe](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/skills/gdp-ts/references/recipe.md).

### Lint protection and release limits

- The rules inspect syntax, without type information. They restrict direct `defineProof` imports/calls, assertions to proof-related types, and direct exports of provers. Strict mode bans other assertions except `as const`, plus explicit `any` upstream. Trusted `**/proofs/**` folders have broad exemptions. The rules do not establish that the check is correct. Sources: [plugin](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/src/lint/plugin.ts), [rule scopes](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/src/lint/shared.ts).
- Main commit `0b6ebee` contains fixes for kind escalation and assertion-free declarations/module augmentation. It adds `no-null-assertion`. The downloaded 0.1.0 artifact lacks these changes. Main still has the value replacement gap; its proposed lint fix is open. Direct-import tracking also misses local re-exports and computed string calls. Sources: [npm metadata](https://registry.npmjs.org/@gdp-ts/core), [merged kind fix](https://github.com/rauchg/gdp-ts/pull/18), [merged lint fix](https://github.com/rauchg/gdp-ts/pull/19), [open value replacement fix](https://github.com/rauchg/gdp-ts/pull/20), [re-export report](https://github.com/rauchg/gdp-ts/issues/16), [computed-call report](https://github.com/rauchg/gdp-ts/issues/3). The last two gaps were checked in source, not reproduced locally.
- Banning the `any` keyword does not stop `any` from an untyped API or `JSON.parse`. Type-aware unsafe-value rules are also needed. `strictNullChecks` and `strictFunctionTypes` matter; `noUncheckedIndexedAccess` blocks the reported `[][0]` proof substitute. Sources: [compiler-option report](https://github.com/rauchg/gdp-ts/issues/14), [forgery report](https://github.com/rauchg/gdp-ts/issues/13), [plugin](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/src/lint/plugin.ts).

### Runtime and maturity

- Each named value gets a frozen `{ value }` wrapper. Each `defineProof` creates a frozen `{ kind }` and a prover; every `prove()` call returns the same proof object and ignores its arguments at runtime. The package has no runtime dependencies. It adds no permission query, policy decision, proof validation, expiry, or revocation. Wrapper freezing is shallow. Sources: [implementation](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/src/index.ts), [package manifest](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/package.json).
- A check can become stale before a write. Transactions or database constraints must handle such races. Callback typing restricts direct return of names/proofs; it does not impose a runtime request lifetime. A returned closure can retain them. This lifetime limit follows from `name()` returning its callback result without runtime tracking. Sources: [documented limits](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/skills/gdp-ts/references/limits.md), [implementation](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/src/index.ts).
- npm lists one release, 0.1.0, published 2026-10-05. Upstream has type tests, runtime tests, shared lint cases, examples, and package smoke checks in CI, including TypeScript 5.4 through 7. These checks are useful, but open gaps and unpublished fixes show that the package is still early. This maturity assessment is an inference from [release metadata](https://registry.npmjs.org/@gdp-ts/core), [CI](https://github.com/rauchg/gdp-ts/blob/0b6ebeeec827b05210f3acfa4149a70dda9a0de5/.github/workflows/ci.yml), and the reports above.

### Local fit and Ultracite 8.1.1

- Installed 8.1.1 exports `ultracite/oxlint/gdp`; no Ultracite upgrade is required. It loads `@gdp-ts/core/lint/plugin`, uses strict assertion rules, and relies on core's `typescript/no-explicit-any`. It permits empty single-base proof interfaces, but keeps `no-redeclare`: use `const prover` beside `interface CanRead`, with distinct names. Its preset does not enable upstream main's new `no-null-assertion`; core already bans non-null assertions. Sources: [installed preset](../../node_modules/ultracite/config/oxlint/gdp/index.mjs), [installed core](../../node_modules/ultracite/config/oxlint/core/index.mjs), [official setup](https://www.ultracite.ai/docs/presets#authorization-proofs-with-gdp-ts).
- The plugin is not bundled with Ultracite. `@gdp-ts/core` is an Ultracite development dependency, not a consumer runtime dependency, and is absent from this repo's lockfile. The published package exports compiled JavaScript and declarations. Its declared floors, TypeScript 5.4 and Oxlint 1.86, fit local 7.0.2 and 1.91.0. Temporary Node 26.13.0 probes loaded it successfully; Bun integration was not tested. Sources: [installed manifest](../../node_modules/ultracite/package.json), [lockfile](../../bun.lock), [published package](https://registry.npmjs.org/@gdp-ts/core/-/core-0.1.0.tgz).
- Hono's middleware reads Better Auth sessions and stores nullable user/session values; it does not check resource permissions. GDP can carry a later business authorization result, while Better Auth continues to authenticate. Sources: [auth instance](../../apps/hono/src/server/auth.ts), [middleware](../../apps/hono/src/server/middleware/auth.ts), [context types](../../apps/hono/src/server/types/hono.ts).
- Current lint has compiler checks and type-aware unsafe-value rules. Both apps inherit `strict: true` from `node.json`; Hono inherits `noImplicitAny: false`, while Effect sets it to `true`. `node.json` does **not** extend `base.json`, so neither app inherits its `noUncheckedIndexedAccess: true`. Hono's effective config was confirmed with `tsc --showConfig`. Load tests extend the base config. Existing test lint exemptions would also need review before any proof trial. Sources: [lint config](../../oxlint.config.ts), [Node config](../../packages/typescript-config/node.json), [base config](../../packages/typescript-config/base.json), [Hono config](../../apps/hono/tsconfig.json), [Effect config](../../apps/effect/tsconfig.json), [load config](../../packages/load/tsconfig.json).

## Proposed layout for a later trial

Keep a future feature's checks and proof types in `apps/hono/src/features/<name>/proofs/`. Keep its protected service/repository in the same feature, so it can demand those proofs without a forbidden `server -> features` import. A feature-local `lib/ids.ts` fits the preset's existing ID-constructor glob. Use `shared/lib/ids.ts` only for pure IDs that several zones need. Keep Better Auth, session access, and database infrastructure in `server`. Put proofs in `server/proofs/` only for facts owned by common server infrastructure. `shared` must stay independent of auth, database, and features. Do not move feature permission policy there merely to share it.

The existing `**/proofs/**` and `**/lib/ids.ts` lint globs match these nested paths. No `src/proofs`, new Fallow zone, rule exception, or cross-feature import is needed. App composition can connect features. Generic database access in `server` remains a path that GDP cannot automatically protect; review callers and the protected API surface. Sources: [ADR-0004](../adr/0004-follow-the-default-bulletproof-boundaries.md), [Hono boundaries](../../apps/hono/.fallowrc.json), [Effect boundaries](../../apps/effect/.fallowrc.json), [load boundaries](../../packages/load/.fallowrc.json), [installed GDP globs](../../node_modules/ultracite/config/oxlint/gdp/index.mjs).

Before adoption, require a release with the relevant fixes, repeat the forgery checks, confirm effective compiler flags, and test the actual allow/deny policy. Keep checking and protected work in one request or Effect execution; do not cache proofs. Keep race protection in the database. These are recommendations, not changes made by this research.
